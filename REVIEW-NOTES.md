# Review notes - feature/v1-04-cli-options

## Items

- A8. Inconsistent CLI option names
- B2. `ml --help` shows the help of `list`, not the command list
- B10. Command descriptions describe the endpoint, not the task

## Original plan

### A8

  - Decision: do (breaking CLI change, done before 1.0).
    - Rule: `-e` (`--environment`), `-c` (`--connection`) and `-d` (`--database`) mean the same in every command.
      Other short flags may differ per command (`logs -f/-t` from/to, `eval -t` txid, ...) and stay as they are.
    - `env show`: the environment moves from a positional argument to `-e/--environment`, default `local`
      (`ml env show` shows `local`, `ml env show -e staging` shows staging); the only positional argument is the
      optional `setting` (`ml env show -e staging host`). Reason: users type `ml env show -e <env>` out of habit
      and get an error. No transition period: `ml env show staging` is read straight away as the setting
      `staging` of `local`, like `ml env show password`.
    - New command `ml env list` lists the environments (what `ml env show` without arguments does today).
    - `env copy`, `env edit`, `env remove` keep the environment name positional - it is their main argument.
    - Short flags that break the rule:
      | Command | Today | New |
      |---|---|---|
      | `health` | `-c` = `--cluster` | `-C` |
      | `env show` | `-c` = `--copy` | `--copy` without a short flag |
      | `env show` | `-d` = `--defaults` | `-D` |
      | `env compare` | `-e` = `--exclude` | `-x` |
      | `env copy` | `-e` = `--edit` | `--edit` without a short flag |
    - Intentional, no change: `http` prints raw by default (`--pretty`) while `eval`/`invoke`/`sample` pretty-print
      by default (`--no-pretty`); `logs` takes a single `-e` (logs from several environments make no sense).
    - Update the CLI docs and the changelog with the renamed flags.

### B2

  - Decision: do. In `main()` (`cli/app.py:178`), when the only argument is `-h` or `--help`, run `list` instead,
    so `ml --help` prints the command list. `ml <command> --help` stays unchanged.

### B10

  - Decision: do. New short descriptions (shown by `ml list`):
    | Command | Description |
    |---|---|
    | `eval` | `Runs XQuery or JavaScript code` |
    | `invoke` | `Runs an XQuery or JavaScript module deployed on the server` |
    | `logs` | `Prints MarkLogic log lines or lists log files` |

      `Uses the /v1/eval endpoint of a REST App Server.` (`/v1/invoke`, `/manage/v2/logs` alike).
    - Other commands keep their descriptions. Update the CLI docs pages that quote them.

## What was added or changed around it

- `env compare -d` (`--defaults`) also broke the rule (`-d` = `--database`) but was missing from the decision's
  table. It is renamed to `-D`, the same letter `env show --defaults` gets, so `--defaults` has one short flag
  across the `env` commands.
- B10, "the endpoint moves to the command's full help as a second sentence": implemented with cleo's `help`
  attribute. `ml eval --help` prints the description under `Description:` and the endpoint sentence under
  `Help:` (cleo prints `Help:` only when it differs from the description, so repeating the first sentence there
  would only duplicate it). `logs` says "the /manage/v2/logs endpoint of the Manage App Server" - the request
  goes to Manage, not to a REST App Server.
- B2: only `ml -h` / `ml --help` with no other argument maps to `list`, as decided. `ml --no-ansi --help` still
  prints the help of `list` (cleo default).
- Changelog: the project has no changelog file; release notes are generated by GitHub from PR labels
  (`.github/release.yml`). The PR for this branch needs the `breaking` label. Suggested release-note text:
  "CLI: `-e/--environment`, `-c/--connection` and `-d/--database` now mean the same in every command.
  `ml env show` takes the environment with `-e` (default `local`) and only the optional setting positionally;
  the new `ml env list` lists environments. Renamed short flags: `health -C` (`--cluster`), `env show -D`
  (`--defaults`), `env compare -D` (`--defaults`), `env compare -x` (`--exclude`); `env show --copy` and
  `env copy --edit` no longer have a short flag. `ml --help` prints the command list."
- Docs: besides the pages named by the options, `docs/cli/index.md` states the `-e/-c/-d` rule once and says
  that `ml --help` lists the commands; README and `docs/guides/environments.md` examples use `ml env show` /
  `ml env list`.

## Report

What changed:

- `ml env show [-e ENV] [<setting>]`: the environment is the `-e/--environment` option, default `local`; the
  only positional argument is the optional setting (`ml env show staging` looks up the setting `staging` in
  `local` and fails with `No setting [staging].`). `--defaults` is `-D`, `--copy` has no short flag.
- New `ml env list [-g]` lists the environment names (what `ml env show` without arguments printed before),
  in `mlclient/cli/commands/env_list.py`, registered in `cli/app.py` and `cli/commands/__init__.py`.
- `health --cluster` is `-C`; `env compare --exclude` is `-x`, `--defaults` is `-D`; `env copy --edit` has
  no short flag.
- `ml -h` / `ml --help` alone print the command list (`main()` in `cli/app.py`).
- New descriptions: `eval` "Runs XQuery or JavaScript code", `invoke` "Runs an XQuery or JavaScript module
  deployed on the server", `logs` "Prints MarkLogic log lines or lists log files", `env show` "Renders one
  MLClient environment's settings", `env list` "Lists MLClient environments". The endpoint sentence is in the
  full help of `eval`, `invoke`, `logs`.

Files: `mlclient/cli/app.py`, `mlclient/cli/commands/{__init__,env_list,env_show,env_compare,env_copy,health,eval,invoke,logs}.py`;
docs `docs/cli/index.md`, `docs/cli/health.md`, `docs/cli/env/{index,list,show,compare,copy}.md`,
`docs/guides/environments.md`, `README.md`, `mkdocs.yml` (nav), `docs/assets/gifs/env-show.tape`;
tests `tests/unit/mlclient/cli/test_ml_client_application.py`,
`tests/unit/mlclient/cli/commands/test_env_{list,show,compare}_command.py`, `test_health_command.py`.

Tests:

  directory named, `--global`/`-g`).

  default, `-e`/`--environment`, a positional argument read as a setting of `local`, the missing `local`

- Short-flag tests for `health -C`, `env compare -x` and `-D`.
